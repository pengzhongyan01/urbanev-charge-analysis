# 可视化看板 · 启动与说明（C09）

## 启动（三选一）

1. **直接双击 `index.html`** —— 推荐，零依赖，完全离线；
2. 本地临时服务：`python -m http.server 8080`，浏览器打开 `http://localhost:8080`；
3. 容器：项目根目录 `docker compose --profile app up -d`（nginx 版）。

> 数据全部内嵌在 `js/data.js`（**全量**：275 个分区、3,850 条预测、2,000 条失衡记录、275 条布点建议（103 个需加桩 + 172 个不加桩）
> + 275 分区维表 + 深圳 9 区底图，约 978 KB），不依赖任何网络请求，答辩现场断网也能完整演示。

## 切换真实接口

`js/common.js` 顶部：

```js
const cfg = { base: 'http://localhost:8080/api/v1', ... };
```

- `base: null`（默认）= 纯离线，读 `data.js`；
- `base` 非空 = 调 `GET {base}/kpi`、`/zones` …，失败自动降级回 `data.js`（顶部会提示）；
- 业务层 `app.js` 零改动。

## 已知问题（答辩要说）

1. `avg_supply` 全时段恒为 0.0036（=1/275）：**用全量数据复算后仍是该值**，说明是 ETL 脚本把分母写成了「分区数」，不是数据缺失；图上不画该曲线，图注已写明；
2. 分区覆盖：全量已 **275/275**，早先「灰色点 = 样例库未覆盖」的说法作废；
3. `station_count` = 275 与分区数同值：ETL 脚本直接取分区列表长度赋值，该字段实为「交通分区数」，看板已改标注为「个交通分区」。
