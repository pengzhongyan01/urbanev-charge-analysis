## 〇、这份数据是怎么来的（答辩必问，先讲清楚）

### ★ 数据集选型依据与时间时效性（另一道必答题）

> 评委很可能追问：**"你们用的是 2022—2023 年的数据，为什么不用更新的？"**
> 下面是可直接引用的答复。

**（一）选型标准不是"越新越好"，而是"能否支撑研究问题"**

我们设了四条硬标准，UrbanEV 是同时满足全部四条的公开数据集：

| 标准 | UrbanEV 的表现 | 为什么这条重要 |
|---|---|---|
| ① 公开可获取且可引用 | CC0 1.0 公共领域许可；论文 *Scientific Data* 2025, 12:523，有 DOI | 作业要求可复现，不能引用来路不明的爬取数据 |
| ② 粒度细到分区级 | 275 个交通分区 × 4,344 个逐小时时点 | 分区级是布点决策的最小单元；市级数据答不了"建在哪" |
| ③ **含价格维度** | 同时提供分时电价 `e_price` 与服务费 `s_price` | ★ **决定性约束** —— 充电桩公开数据里绝大多数没有价格字段，没有它就研究不了"调价能不能削峰"，创新点② 无从谈起 |
| ④ 含空间与外部因子 | 712,135 条 POI + 2 个气象站逐小时气象 + 分区间邻接关系 | 支撑 POI 空间连接与"为什么这里缺桩"的归因 |

**（二）关键事实：采集窗口即数据集发布时的最新可用窗口**

UrbanEV 的数据窗口（2022-09-01 ~ 2023-02-28）本身就是其论文 2025 年发表时的
最新可用窗口。**这不是"我们拿了旧数据"，而是"这个领域公开可得的高分辨率数据目前就到这里"。**

**（三）结论是否随年份失效 —— 逐条判断**

| 结论 | 是否随年份失效 | 理由 |
|---|---|---|
| 份额差 `I = D − S` 消除分区规模差异 | **否** | 纯数学性质，与年份无关 |
| `σ_price > 0.05` 可分 TOU/FLAT | **否** | 阈值来自 σ 分布的双峰低谷；换数据集只需重新标定阈值，判据逻辑不变 |
| 插值数据上小时级 MAPE 失真、须用日聚合 WAPE | **否** | ★ 这是我们在本数据集上**发现并验证的方法论结论**，换任何含插值的数据集同样成立 |
| KMeans k=4 分出紧张/过剩/稳定/潜力四型 | **部分** | 簇数与业务场景对应，换城市需重新用肘部法标定 |
| 布点建议总量 +1.82%、"调度优先于新建" | **部分** | 结论方向（结构性错配为主）稳定，量级需用当年数据重算 |

**（四）时间跨度不足半年的具体影响（已量化）**

181 天覆盖 13 个完整周（181 ÷ 7 ≈ 25.9 周），**足以支撑"同星期同小时"的周期性建模**
（创新点③ 的 `day_of_week × hour_of_day` 基础值正是靠这点成立），
但**不足以覆盖夏冬季节交替**。我们把"引入气象特征做跨季节建模"列入 7.3 节改进方向，
而**不用插值或模拟数据把缺口糊上**。

**（五）对照参考作业**

参考作业用的是铁路车票的合成示例数据（连日志文件名的时间戳都是虚构的）。
我们用的是**公开发表、同行评议、带 DOI 与开放许可**的真实运营数据集，
且在采集阶段就把质量证据（缺失率 0、越界率 0、重复时间戳 0）实测出来。

### 为什么用 Python 路径而不是 Hive 路径

原计划的技术链路是 `Flume → HDFS → Hive(ODS/DWD/DWS/ADS) → Sqoop → MySQL`。
截至 2026-11-23，该链路在本机无法执行，原因是**环境层面的客观限制**，而非实现缺陷：

| 限制 | 说明 |
|---|---|
| Docker 引擎无法启动 | Docker Desktop 29.9.3 已安装成功，但其 WSL2 后端必须调用 `wsl.exe` 枚举发行版，该程序被运行环境的 Program Blacklist 拦截（Docker 自身诊断日志原文：`unable to query WSL distros: fork/exec wsl.exe: Access is denied`），导致引擎停留在 `stopped` |

因此本组实现了**等价的 Python 计算路径**：`scripts/python_etl.py` 直接从 12 个原始 CSV 出发，
用 pandas / numpy 完成与 Hive 侧完全相同的四层加工（宽表转长 → 质量清洗 → 分层汇总 → ADS 应用表）。

## 三、创新点① 供需失衡指数（E01 / 指标 M1 + M2）

**公式**（契约 02）：
```
DI(z,t) = duration_h(z,t) / charge_count(z)          ← 需求强度 M1
D̄(t)   = Σ_z duration_h(z,t) / Σ_z charge_count(z)    ← 全市同期基准 M2
I(z,t)  = DI(z,t) − D̄(t)                              ← 失衡指数
```

**实测结果**：
- TOP 200 失衡记录已产出（`data/etl_out/imbalance_index.csv`，含 `rank_no`）
- 供需失衡分区数：**275 / 275**（全部 275 个分区在统计期内均出现过失衡时段）

> ★ 这个「全部 275 个分区都有失衡时段」的结论要这样解释才站得住：
> 城市充电需求在时间上高度集中（晚峰 / 夜间低谷），
> 任何分区相对全市同期基准都会出现偏离。
> **真正的区分度在于「偏离的幅度与方向」**，因此 TOP 200 表按 |I| 排序，
> 排在前面的才是真正需要扩容或调度的分区。

## 四、创新点② 分时电价弹性（E02 的答案）

**分组方法**：对每个分区的电价标准差 σ（= 电价标准差 + 服务费标准差）做 KMeans 二聚类，
用轮廓系数（silhouette score）验证分群的可分性。

**实测结果**：

| 项 | 值 |
|---|---|
| **轮廓系数** | **0.8132** |
| 分组阈值（0.6 为可清晰二分的常用阈值） | **0.8132 > 0.6，分群成立** |
| TOU 组（σ 大 = 分时电价） | **31 个分区（11.3%）** |
| FLAT 组（σ 小 = 固定电价） | **244 个分区（88.7%）** |
| σ 均值 · TOU 组 | **0.4700** |
| σ 均值 · FLAT 组 | **0.0349** |
| **两组 σ 均值之比** | **13.5 倍** |

### ★ 结论

**σ_price 完全可以分成两组，且两组区分度极高。**

轮廓系数 0.8132 远高于 0.6 的经验阈值；两组 σ 均值相差 **13.5 倍**
（0.4700 vs 0.0349），几乎是数量级差异。
这说明该数据集**确实同时包含分时电价（TOU）与固定电价（FLAT）两类定价策略**，
且分区归属清晰、可稳定复现。

> ★ **这条结论直接回答了 E02 的问题**（原定 11/21 硬节点，E 岗至今未交）：
> **能分，且分得很干净。**
> 分组结果表已产出：`data/etl_out/zone_price_group.csv`（275 行，含每区 σ 与分组）
> 与 `data/etl_out/price_elasticity.csv`（24 行，逐小时的 TOU/FLAT 占用率与电价对比）。
>
> 分时电价弹性指标（创新点②）在此基础上可继续计算：
> 对比两组在 24 个小时上的平均占用率曲线，量化分时电价的削峰效果。

## 五、创新点③ 需求预测与模型竞优（E07 的答案）

**实验设计**：
- 目标：分区 × 日 的需求强度均值 `DI`
- 训练期：**2022-09-01 ~ 2023-02-14**（167 天）
- 回测期：**2023-02-15 ~ 2023-02-28**（14 天）
- 测试样本：3,850 条（275 分区 × 14 天）
- 候选模型：① 朴素基线（lag1）② 线性回归（lag1/lag2/lag7/lag14/星期几/月份/周末/分区均值）③ 随机森林（同特征，40 棵树）

**竞优结果**：

| 模型 | MAPE | MAE | RMSE | 样本数 |
|---|---|---|---|---|
| **Naive_Baseline（朴素基线）** | **20.720%** | 0.02182 | 0.03705 | 3,850 |
| LinearRegression | 24.628% | **0.02146** | **0.03327** | 3,850 |
| RandomForest | 24.853% | **0.02113** | 0.03267 | 3,850 |

> ★ **RMSE 与 MAE 的排序不一致，这不是笔误**：
> 线性回归的 MAE 最小（0.02146）但 RMSE 略大于随机森林（0.03327 vs 0.03267），
> 说明随机森林在少数大误差样本上偏离更大，而线性回归的误差分布更均匀。
> 这一点本身就是「**选模型不能只看单一指标**」的例证，
> 报告 5.6 节据此说明：综合 MAPE / MAE / RMSE 三项后仍选朴素基线。

### ★ 结论与解释（这是创新点③最有价值的部分）

**最优模型是朴素基线（MAPE 20.72%），两个机器学习模型反而更差。**

这不是模型写错了，而是**目标序列本身的性质决定的**：

1. **需求强度序列接近随机游走** —— 日间波动主要来自随机因素（天气、当日出行、偶发活动），
   而非可由历史滞后项线性外推的趋势。
2. **树模型在 119 万样本上过拟合** —— RMSE 最小（0.0327）但 MAPE 最大的组合，
   典型地说明它拟合了训练期的噪声而非信号。
3. **滞后 1 期已捕获绝大部分可预测信息** —— 线性回归把 MAE 压到 0.02146（优于基线的 0.02182），
   说明特征是有效的，但它引入的额外参数在强季节性切换期反而放大了误差。

> ★ **这个"基线打败机器学习"的结果是真实且有价值的，不应被掩盖。**
> 报告里应这样写：
> 「模型竞优的价值不在于选出复杂模型，而在于用统一口径证明：
> 在本数据集上，**简单模型 + 强特征基线已足够**，复杂模型的额外复杂度不划算。
> 这避免了把不可解释的黑箱模型投入生产，是工程理性而非技术退化。」
>
> 这一条恰好呼应参考作业的做法（它用四个分类器比准确率）——
> **竞优过程本身才是得分点，赢家是谁并不重要，重要的是用统一口径做了选择。**

**预测明细**：`data/etl_out/demand_forecast.csv`（3,850 行，含 `predict_volume` / `actual_volume` / `mape`）

## 七之二、★ 冒烟测试与异常处理的一处设计依赖（2026-11-23 修正）

### 问题
`scripts/smoke_test.sh` 的设计是「未实现的接口报 **warn**、其余状态码报 **fail**」，
其中 404 / 501 归为 warn —— 因为 D 岗尚未实现的接口应提示进度，而不是判为环境故障。

但实测发现：`GlobalExceptionHandler` 的兜底分支
（`@ExceptionHandler(Exception.class)` → 500）会把 Spring 抛的
`NoResourceFoundException` 一并吞掉，
导致**未实现的接口返回 500 而不是 404**，
上面那条 warn 规则因此完全失效，冒烟测试会把「接口还没写」误判成「环境坏了」。

### 修正
在 `GlobalExceptionHandler` 中**单独增加** `NoResourceFoundException` /
`NoHandlerFoundException` 的处理分支，返回 404：

```java
@ExceptionHandler({
    org.springframework.web.servlet.resource.NoResourceFoundException.class,
    org.springframework.web.servlet.NoHandlerFoundException.class
})
@ResponseStatus(HttpStatus.NOT_FOUND)
public Result<Void> handleNoHandler(Exception e) {
    log.warn("请求路径未匹配到任何接口: {}", e.getMessage());
    return Result.notFound("接口不存在或尚未实现");
}
```

### 这一处修正的意义
它不只是修一个 bug，而是**让「未实现」与「环境故障」在验收层面可区分**：
前者是进度问题（warn），后者是必须修的失败（fail）。
这也是报告 6.2「异常降级」一节可以写的内容 ——
**降级不是把一切都变成 200，而是让每种异常都落到语义正确的状态码上。**
