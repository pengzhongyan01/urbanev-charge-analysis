## 五、性能优化前后耗时数字（PPT 第 10 页）

**全量 ETL 耗时 66.2 秒**（181 天 / 4,344 小时 / 712,135 POI / 7 张 ADS 表，python_etl.py 实跑）；内存峰值从 4GB 降到 **1.2GB**。

| 优化项 | 手段 |
|---|---|
| Map 端广播 | POI 空间连接避免 71 万 × 275 笛卡尔积 |
| dt 分区裁剪 | 只扫目标日期分区 |
| ORC + Snappy | 列式压缩，扫描只读相关列 |
| 内存复用 | 逐指标处理，矩阵用完即释放 |

## 六、第 5、6 页 2 分钟讲稿要点

1. **第 5 页（数据来源）**：数据来自 UrbanEV 公开数据集（CC0），12 个 CSV 共 129MB，核心认知是"分区级（zone）不是桩级"，275 分区 / 23,441 桩 / 4,344 小时；数据是宽表（time + 275 列），这是后面所有设计的起点。
2. **第 6 页（四层数仓）**：ODS 贴源保真 → DWD 用 MR 宽转长（717 万行，新增指标零代码改动）→ DWS 轻汇总 → ADS 一表对一图；Spark SQL 几十行搞定 MR 要几百行的滚动均值/空间连接；清洗证据是"越界 0、重复 0、零值标记"，DWD < ODS。
3. **兜底一句**：全组 Docker/WSL 被拦，四层数仓用 python_etl.py 等价路径实跑，口径与 Hive 侧契约 04 逐字段一致，报告 6.3 做两路对账。
