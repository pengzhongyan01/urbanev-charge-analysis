## 零、基础数据口径（所有人必须对齐）

| 项 | 定义 |
|---|---|
| 分区维度 | `zone_id`（字符串），共 **275** 个 |
| 时间维度 | `hour_ts`（`yyyy-MM-dd HH:mm:ss`），共 **4,344** 个逐小时时点 |
| 时间范围 | **2022-09-01 00:00 ~ 2023-02-28 23:00**（181 天） |
| 充电桩数 | `charge_count`（来自 `inf.csv`），全市合计 **23,441** 个 |
| 长表结构 | `uev_dwd.zone_hour_metric(zone_id, hour_ts, hour_of_day, day_of_week, metric, value, is_zero)` + 分区键 `dt` |
| `metric` 取值 | `occupancy` / `duration` / `volume` / `volume_11kw` / `e_price` / `s_price` |
| 单位 | occupancy 比例 0~1；duration 小时；volume kWh；e_price / s_price 元/kWh |

> 🔴 **单位警告**：`occupancy` 是**比例**不是百分数，展示时需 ×100。
> `duration` 的 `value` 单位是**小时**（不是分钟）。

## 二、创新指标（3 项）★ 答辩核心

### ★ 创新点① 峰谷供需失衡指数

| 项 | 内容 |
|---|---|
| 名称 | `imbalance_index` |
| **问题背景** | 分区间充电桩基数差异巨大（4 ~ 446 个），**绝对量不可比**。直接比占用率或充电量会误判：桩多的分区天然数值大，不代表更紧张。 |
| **核心思想** | 把需求与运力都归一化为"占全市同期的份额"，用**份额之差**衡量供需错配。这样不同规模的分区可以横向比较。 |
| **公式** | ```D(z,t) = demand(z,t) / Σ_z' demand(z',t)      需求份额S(z,t) = charge_count(z) / Σ_z' charge_count(z')   运力份额★ I(z,t) = D(z,t) − S(z,t)``` |
| **取值含义** | `I > 0` → 该分区此占需求的份额 **>** 占运力的份额 → **供不应求**<br>`I < 0` → 运力相对闲置<br>`I = 0` → 与全市供需结构一致 |
| **取值范围** | [−1, 1]（实际约 [−0.02, 0.02]） |
| 来源表 | `uev_dws.zone_day_hour` + `uev_dwd.dim_zone_info` |
| SQL | 见 `hadoop/spark/ads_metrics.sql` 创新点① 章节（完整可跑） |
| 落地表 | `uev_ads.imbalance_index` |
| 对应图表 | **失衡指数 TOP10 横向柱状图** |
| **验收标准** | ① 输出约 275×24 ≈ 6,600 行<br>② 正负值都有<br>③ TOP10 应包含 CBD 类分区（南山 308、福田 302 等）——若无则说明归一化写错 |
| **计算结果** | 【待 E 填：TOP10 列表 + 文字结论】 |

> 💡 **答辩话术**：
> "我们没有直接用占用率，因为分区规模差异太大。
> 我们用**份额差**——这个指标消除了规模差异，让 4 个桩的分区和 446 个桩的分区可以公平比较。"

### ★ 创新点② 分时电价弹性分析

| 项 | 内容 |
|---|---|
| 名称 | `price_elasticity` |
| **问题背景** | 分时电价政策一直在推广，但"到底有没有真的削峰填谷"缺少**基于数据的实证**。绝大多数充电桩数据集没有价格信息，无法做这个对比。 |
| **核心思想** | UrbanEV 同时提供分区级的**价格时序**与**占用率时序**，且价格时序本身就能反推出哪些区实行分时电价——这是本数据集独有的优势。 |
| **步骤一：分区类型识别** | ```σ_price(z) = STDDEV_POP(e_price(z,·))σ_price(z) > 阈值(0.05)  →  TOU 区（分时电价）σ_price(z) ≈ 0         →  FLAT 区（固定电价）``` |
| **步骤二：削峰效果计算** | ```PEAK_RATIO(T)   = AVG(occupancy) where 17 ≤ hour_of_day ≤ 19VALLEY_RATIO(T) = AVG(occupancy) where  0 ≤ hour_of_day ≤  6★ ELASTICITY(T) = PEAK_RATIO(T) − VALLEY_RATIO(T)``` |
| **判读规则** | `ELASTICITY` **越小** → 峰谷被压得越平 → **削峰填谷效果越好** |
| **来源表** | `uev_dwd.zone_hour_metric` + `uev_dwd.dim_zone_info` |
| SQL | 见 `hadoop/spark/ads_metrics.sql` 创新点② 章节 |
| 落地表 | `uev_ads.price_elasticity` |
| 对应图表 | **TOU vs FLAT 双曲线对比图** |
| **验收标准** | ① TOU 与 FLAT 两组均非空<br>② **TOU 组的 ELASTICITY 应小于 FLAT 组**——若反了，说明阈值或归一化有问题<br>③ 报告中注明"这是观测性关联，不做因果推断" |
| **计算结果** | 【待 E 填：两组的 ELASTICITY 数字 + 结论】 |

> 💡 **答辩话术**：
> "全深圳 275 个分区的分时电价策略是公开信息，
> 但**把 TOU 区和 FLAT 区的占用率曲线放在一起对比**——这个分析角度是我们独有的。"

### ★ 创新点③ 充电需求预测与布点扩容建议

| 项 | 内容 |
|---|---|
| 名称 | `demand_forecast` + `expansion_suggestion` |
| **问题背景** | "知道哪里缺桩"之后，运营方还要回答"**建多少桩、建在哪、什么优先级**"。 |
| **为什么不选 LSTM** | ① 答辩现场换电脑跑不起来是灾难<br>② 数据是 275 分区的强周期时序，统计方法足够<br>③ **"我们为什么不用 LSTM"比"我们用了 LSTM"更能体现工程判断力** |
| **预测公式** | ```基础值 = AVG(volume(z, 同一 day_of_week, 同一 hour_of_day))   —— 前 174 天训练趋势因子 γ = AVG(近7天 volume) / AVG(全期 volume)★ predict = 基础值 × γ``` |
| **回测方案** | 前 174 天（2022-09-01 ~ 2023-02-21）训练，最后 7 天（02-22 ~ 02-28）验证，报告 MAPE |
| **布点建议规则** | ```建议新增桩数 = ⌈ 峰值失衡指数 I_max(z) × charge_count(z) × 0.3 ⌉优先级 = 按 I_max(z) 降序（1 = 最高）``` |
| **0.3 系数说明** | 保守规划系数——一次规划不宜过大，分期建设更稳妥。**这个系数是业务判断，需在报告中说明理由** |
| 来源表 | `uev_dws.zone_day_hour` + `uev_ads.imbalance_index` |
| SQL | 见 `hadoop/spark/ads_metrics.sql` 创新点③ 章节 |
| 落地表 | `uev_ads.demand_forecast`、`uev_ads.expansion_suggestion` |
| 对应图表 | **预测值 vs 实际值折线图** + **建议清单表格** |
| **验收标准** | ① MAPE < 15% 可写进报告<br>② 若 MAPE > 25%，改用"近 7 天同小时均值"（去掉趋势因子）<br>③ 建议清单的 `reason` 字段必须是**完整中文句子**，直接进前端看板 |
| **计算结果** | 【待 E 填：MAPE 数字 + TOP10 建议清单】 |

> 💡 **答辩话术**：
> "为增强工程可复现性与答辩现场的可演示性，本系统采用基于同周期移动平均的统计预测方法，
> 深度学习序列模型列入后续工作展望。"

### ★ 创新点④ 分区聚类画像（可选增量，基于老师高分思路补充）

| 项 | 内容 |
|---|---|
| 名称 | `zone_cluster` |
| **为什么加** | 老师给的高分思路图里「数据分析」被标红且独立成段，说明分析深度是评分重点。我们已有三个创新点都是"规则驱动/统计对比"，聚类补上"**数据驱动发现未知结构**"这一维度 |
| **核心思想** | 不预设结论，用算法自己告诉我们 275 个分区有哪几类 —— 每一类的运营策略应该不同 |
| **方法** | K-Means（**Spark MLlib**，不需 Python/sklearn），7 维特征，k=4 |
| **特征向量** | `X(z) = [avg_occupancy, peak_valley_gap, occupancy_std, avg_duration, poi_density, pile_density, price_std]` |
| **三个必写的技术点** | ① **标准化**：桩密度量级可能是占用率的千倍，不标准化则聚类被单一特征主导<br>② **固定种子** `setSeed(42)`：保证结果可复现，别人能验证<br>③ **肘部法选 k**：给 k=2~6 的 WCSS 曲线说明为什么选 4 |
| 来源表 | `uev_dws.zone_cluster_features` |
| 代码骨架 | `hadoop/spark/ZoneClustering.scala` + `hadoop/spark/zone_clustering.sql` |
| 落地表 | `uev_ads.zone_cluster` |
| **预期簇结构** | 紧张型（占用高/桩密度低）· 过剩型（占用低/桩密度高）· 稳定型（各项居中）· 潜力型（POI 密度高/桩少） |
| **★ 关键互证** | 紧张型簇的平均失衡指数应显著高于其他簇 —— 两种独立方法得到一致结论，是本节最有说服力的地方 |
| 对应图表 | **275 个分区按簇着色的地图**（PPT 高光页）、簇特征雷达图 |
| **验收标准** | ① 特征表 275 行无 NULL<br>② 重复运行结果一致<br>③ 四簇规模不极端<br>④ 互证成立（紧张型 avg_imbalance 最高）<br>⑤ 报告写清标准化/种子/肘部法三点 |
| **优先级** | ★ **可选增量** —— 11/24 前若三个创新点未算完，直接砍掉，不影响主线 |
