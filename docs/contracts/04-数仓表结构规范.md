## 一、四层职责

| 层 | 职责 | 谁看 |
|---|---|---|
| **ODS** | 贴源存放，**保留宽表原貌**（275 列），不做任何加工 | 苏静 |
| **DWD** | **宽转长 + 清洗 + 补齐维度**：一行 = 一个分区在一个小时的一个指标 | 苏静 / 姬婷婷 |
| **DWS** | 轻度汇总：按天聚合、滚动均值、峰谷标识、分区供给画像 | 苏静 / 姬婷婷 |
| **ADS** | 应用指标层：**一张表对应前端一个图表**，前端只查 ADS | 苏静 / 杨姗姗 / 贺欢欢 |

> 🔑 **本项目数仓的核心技术点就在 ODS → DWD 这一步：宽表 explode 成标准长表。**
> 这是 Hive 里最经典的 ETL 操作，也是报告第三章"数据清洗"章节最有说服力的内容。

## 二、库表命名规范

```
库名：uev

ODS 层  uev.ods_<源文件名>        例：uev.ods_occupancy（宽表，275 列）
维表    uev.dim_<表名>             例：uev.dim_zone_info
DWD 层  uev.dwd_<主题>_<粒度>      例：uev.dwd_zone_hour_metric
DWS 层  uev.dws_<主题>_<粒度>      例：uev.dws_zone_day
ADS 层  uev.ads_<主题>             例：uev.ads_imbalance_index
```

## 三、ODS 层（宽表原样落地）

### 3.1 自动生成 DDL

275 列手写不现实，用脚本生成：

```bash
python3 hadoop/hive/gen_ddl.py > ddl_ods.sql
hdfs dfs -put ddl_ods.sql /tmp/
beeline -u jdbc:hive2://localhost:10000 -f /tmp/ddl_ods.sql
```

脚本已写好并验证可用（`hadoop/hive/gen_ddl.py`），生成 9 张表：
`ods_occupancy`、`ods_duration`、`ods_volume`、`ods_volume_11kw`、`ods_e_price`、`ods_s_price`、`ods_inf`、`ods_adj_matrix`、`ods_distance_matrix`

### 3.2 手写一张示例（了解结构即可，实际用脚本）

```sql
CREATE DATABASE IF NOT EXISTS uev_ods;

CREATE TABLE IF NOT EXISTS uev_ods.occupancy (
  `time` STRING  COMMENT '小时时间戳 yyyy-MM-dd HH:mm:ss',
  `102` DOUBLE, `104` DOUBLE, `105` DOUBLE
  -- ... 共 275 个分区列
)
COMMENT '充电桩占用率（宽表）'
STORED AS ORC
TBLPROPERTIES ('orc.compress'='SNAPPY');
```

### 3.3 数据入 ODS

```bash
# 1. 原始 CSV 上传到 HDFS
hdfs dfs -mkdir -p /uev/ods/occupancy
hdfs dfs -put -f data/raw/occupancy.csv /uev/ods/occupancy/

# 2. 若是外部表，用 LOAD DATA 指向 HDFS 路径
LOAD DATA INPATH '/uev/ods/occupancy/occupancy.csv'
  INTO TABLE uev_ods.occupancy;
```

> ⚠️ **注意时间字段格式**：`time` 列是 `2022-09-01 00:00:00` 字符串，
> 直接 `PARTITIONED BY (dt)` 不会自动分区，**要么在 DWD 层处理，要么加分区列**。

## 四、DWD 层（★ 核心：宽转长 + 清洗）

### 4.1 主表：指标长表

```sql
CREATE DATABASE IF NOT EXISTS uev_dwd;

CREATE TABLE IF NOT EXISTS uev_dwd.zone_hour_metric (
  zone_id      STRING COMMENT '交通分区编号',
  hour_ts      STRING COMMENT '小时时间戳 yyyy-MM-dd HH:mm:ss',
  hour_of_day  INT    COMMENT '小时 0-23',
  day_of_week  INT    COMMENT '星期 1-7',
  metric       STRING COMMENT 'occupancy/duration/volume/volume_11kw/e_price/s_price',
  value        DOUBLE COMMENT '指标值（清洗后，异常置 NULL）',
  is_zero      INT    COMMENT '1=原值为0（疑似缺失）0=正常'
)
COMMENT '各指标标准化长表（由 ODS 宽表 explode 而来，已清洗）'
PARTITIONED BY (dt STRING COMMENT '日期分区键 yyyy-MM-dd')
STORED AS ORC
TBLPROPERTIES ('orc.compress'='SNAPPY');
```

**数据量估算**：275 分区 × 4,344 小时 × 6 指标 ≈ **717 万行**（很适合 Spark 处理）

### 4.2 两种生成方式（选一种，推荐方式 A）

#### 方式 A：MapReduce explode（★ 推荐）

代码骨架已写好：`hadoop/mr/WideToLong.java`

```bash
# 打包
cd hadoop/mr
javac -cp $(hadoop classpath) WideToLong.java
jar cf uev-mr.jar WideToLong*.class

# 运行（每个指标一次）
hadoop jar uev-mr.jar com.uev.mr.WideToLong \
  /uev/ods/occupancy/occupancy.csv /uev/dwd/long/occupancy \
  -D uev.metric.name=occupancy
```

**为什么推荐 MR**：
1. Hive 的 `stack()` 要硬编码 275 个列名，代码无法维护
2. MR 动态遍历所有列，**加指标不用改代码**
3. 这是"熟练掌握 Hadoop"评分点的**直接证据**，答辩时讲得清楚

#### 方式 B：Hive SQL（快速验证用）

```sql
-- Hive 3.x 支持 LATERAL VIEW stack，但 275 列名需脚本生成
INSERT OVERWRITE TABLE uev_dwd.zone_hour_metric PARTITION (dt)
SELECT
    t.zone_id,
    t.hour_ts,
    CAST(SUBSTR(t.hour_ts, 12, 2) AS INT)  AS hour_of_day,
    CAST(DATE_FORMAT(TO_DATE(t.hour_ts), 'u') AS INT) AS day_of_week,
    'occupancy' AS metric,
    t.value,
    CASE WHEN t.value = 0 THEN 1 ELSE 0 END AS is_zero,
    REGEXP_REPLACE(SUBSTR(t.hour_ts, 1, 10), '-', '') AS dt
FROM (
    SELECT `time` AS hour_ts, `102` AS zone_id, `102` AS value FROM uev_ods.occupancy
    -- 275 组 UNION ALL
) t;
```

### 4.4 维表

```sql
CREATE TABLE IF NOT EXISTS uev_dwd.dim_zone_info (
  zone_id      STRING COMMENT '分区编号（= inf.csv 的 TAZID）',
  longitude    DOUBLE,
  latitude     DOUBLE,
  charge_count INT    COMMENT '充电桩数',
  area         DOUBLE,
  perimeter    DOUBLE,
  poi_lifestyle     INT COMMENT '生活服务类 POI 数',
  poi_business      INT COMMENT '商务居住类 POI 数',
  poi_food          INT COMMENT '餐饮服务类 POI 数',
  poi_total         INT COMMENT 'POI 总数',
  is_tou_zone  INT    COMMENT '是否分时电价区（由 e_price 标准差反推）',
  price_std    DOUBLE COMMENT '电价时序标准差',
  price_peak   DOUBLE COMMENT '峰电价',
  price_valley DOUBLE COMMENT '谷电价',
  price_gap    DOUBLE COMMENT '峰谷价差'
)
COMMENT '分区综合维度表（E 组创新点②依赖此表）'
STORED AS ORC;
```

> 🔴 **`is_tou_zone` 的生成逻辑（姬婷婷的创新点②入口）**：
> ```sql
> INSERT OVERWRITE TABLE uev_dwd.dim_zone_info
> SELECT
>   i.TAZID, i.longitude, i.latitude, i.charge_count, i.area, i.perimeter,
>   p.poi_lifestyle, p.poi_business, p.poi_food, p.poi_total,
>   CASE WHEN e.price_std > 0.05 THEN 1 ELSE 0 END AS is_tou_zone,
>   e.price_std, e.price_peak, e.price_valley,
>   e.price_peak - e.price_valley AS price_gap
> FROM uev_ods.inf i
> LEFT JOIN (-- POI 空间连接聚合结果，由 MR 计算
+             SELECT zone_id, ... FROM uev_dwd.zone_poi_count
+         ) p ON i.TAZID = p.zone_id
+ LEFT JOIN (-- 电价波动统计
+             SELECT zone_id, STDDEV_POP(value) AS price_std,
+                    MAX(value) AS price_peak, MIN(value) AS price_valley
+             FROM uev_dwd.zone_hour_metric
+             WHERE metric = 'e_price' GROUP BY zone_id
+         ) e ON i.TAZID = e.zone_id;
+ ```
> ⚠️ **坑**：`inf.csv` 行序 ≠ 时序表列序，**必须按 TAZID 显式 join，禁止按行号对齐**。

## 五、DWS 层（轻度汇总）

```sql
CREATE DATABASE IF NOT EXISTS uev_dws;

-- 分区日汇总
CREATE TABLE IF NOT EXISTS uev_dws.zone_day (
  zone_id         STRING,
  dt              STRING,
  avg_occupancy   DOUBLE COMMENT '日均占用率',
  max_occupancy   DOUBLE,
  avg_duration    DOUBLE,
  total_volume    DOUBLE,
  avg_e_price     DOUBLE,
  peak_hour       INT    COMMENT '峰值小时',
  valley_hour     INT    COMMENT '谷值小时',
  peak_valley_gap DOUBLE COMMENT '峰谷差',
  occupancy_std   DOUBLE COMMENT '日内波动率'
)
COMMENT '分区日粒度汇总'
PARTITIONED BY (dt STRING)
STORED AS ORC;

-- 分区时段画像（峰谷分析）
CREATE TABLE IF NOT EXISTS uev_dws.zone_hour_profile (
  zone_id        STRING,
  hour_of_day    INT,
  avg_occupancy  DOUBLE,
  avg_duration   DOUBLE,
  avg_volume     DOUBLE,
  sample_days    INT
)
COMMENT '分区 x 小时 画像表（峰谷分析用）'
STORED AS ORC;

-- 分区日 x 小时画像（供需失衡计算用）
CREATE TABLE IF NOT EXISTS uev_dws.zone_day_hour (
  zone_id        STRING,
  dt             STRING,
  hour_of_day    INT,
  occupancy      DOUBLE,
  duration_h     DOUBLE,
  volume_kwh     DOUBLE,
  e_price        DOUBLE,
  s_price        DOUBLE,
  charge_count   INT
)
COMMENT '分区 x 日 x 小时 事实表（ADS 层直接消费）'
STORED AS ORC;
```

## 六、ADS 层（一张表 = 前端一个图表）

```sql
CREATE DATABASE IF NOT EXISTS uev_ads;

-- ① KPI 概览（首页 5 个指标卡）
CREATE TABLE IF NOT EXISTS uev_ads.dashboard_kpi (
  dt               STRING,
  station_count    INT,      -- 充电站/分区数
  pile_count       INT,      -- 充电桩总数
  avg_occupancy    DOUBLE,   -- 平均占用率
  total_volume     DOUBLE,   -- 累计充电量
  avg_duration     DOUBLE,   -- 平均充电时长
  imbalance_zones  INT,      -- 供需失衡分区数
  compute_time     TIMESTAMP
) STORED AS ORC;

-- ② 分区占用率（前端热力图 / 地图）
CREATE TABLE IF NOT EXISTS uev_ads.zone_occupancy (
  zone_id      STRING,
  longitude    DOUBLE,
  latitude     DOUBLE,
  avg_occupancy DOUBLE,
  max_occupancy DOUBLE,
  charge_count INT,
  poi_total    INT
) STORED AS ORC;

-- ③ 24 小时供需曲线（前端折线图）
CREATE TABLE IF NOT EXISTS uev_ads.hourly_supply_demand (
  hour_of_day   INT,
  avg_occupancy DOUBLE,
  avg_demand    DOUBLE,   -- 归一化需求强度
  avg_supply    DOUBLE,   -- 归一化运力供给
  gap           DOUBLE,   -- 供需差
  imbalance     DOUBLE    -- 失衡指数
) STORED AS ORC;

-- ④ 供需失衡指数 TOP N（前端柱状图）★ 创新点①
CREATE TABLE IF NOT EXISTS uev_ads.imbalance_index (
  zone_id      STRING,
  longitude    DOUBLE,
  latitude     DOUBLE,
  dt           STRING,
  hour_of_day  INT,
  demand       DOUBLE,
  supply       DOUBLE,
  imbalance    DOUBLE,   -- I(z,t) = D(z,t) - D̄(t)
  rank_no      INT
) STORED AS ORC;

-- ⑤ 电价弹性对比（前端双曲线图）★ 创新点②
CREATE TABLE IF NOT EXISTS uev_ads.price_elasticity (
  price_type    STRING,   -- TOU / FLAT
  hour_of_day   INT,
  avg_occupancy DOUBLE,
  zone_count    INT,
  avg_price_gap DOUBLE

-- ⑥ 需求预测结果（前端预测曲线）★ 创新点③
CREATE TABLE IF NOT EXISTS uev_ads.demand_forecast (
  zone_id      STRING,
  forecast_date STRING,
  hour_of_day  INT,
  predict_volume DOUBLE,
  actual_volume  DOUBLE COMMENT '回测期实际值',
  mape         DOUBLE
) STORED AS ORC;

-- ⑦ 布点扩容建议（前端建议看板）★ 创新点③
CREATE TABLE IF NOT EXISTS uev_ads.expansion_suggestion (
  zone_id        STRING,
  longitude      DOUBLE,
  latitude       DOUBLE,
  current_piles  INT,
  suggested_piles INT,
  priority       INT,     -- 1=最高优先级
  reason         STRING,  -- 文字结论
  avg_occupancy  DOUBLE,
  peak_gap       DOUBLE
) STORED AS ORC;
```

## 七、Sqoop 导出到 MySQL（杨姗姗用）

```bash
# 建 MySQL 目标表（后端 D 组负责建，这里给建表语句供参考）
# 导出 ADS 层
sqoop export \
  --connect jdbc:mysql://localhost:3306/uev_charge \
  --username root --password uev123456 \
  --table dashboard_kpi \
  --hcatalog-table uev_ads.dashboard_kpi \
  --hcatalog-database uev_ads \
  --hive-import \
  --m 1 \
  --columns "dt,station_count,pile_count,avg_occupancy,total_volume,avg_duration,imbalance_zones,compute_time" \
  --input-fields-terminated-by '\001' \
  --mysql-non-auto-increment \
  --null-string '\\N' \
  --null-non-string '\\N'
```

> ⚠️ **MySQL 目标表字段类型要与 Hive 一致**，`compute_time` 这类 TIMESTAMP 建议在 MySQL 里用
> `VARCHAR(30)` 存字符串，避免 Sqoop 类型映射踩坑（**杨姗姗注意，这是联调期最容易卡住的地方**）。

## 八、建表顺序与检查清单

| 步骤 | 操作 | 命令 | 验收 |
|---|---|---|---|
| 1 | 建库 | `CREATE DATABASE uev_ods/dwd/dws/ads` | `show databases;` 能看到 |
| 2 | ODS 建表 | `python3 hadoop/hive/gen_ddl.py > ddl_ods.sql` | 9 张表建成 |
| 3 | ODS 入数据 | `hdfs dfs -put` + `LOAD DATA` | `SELECT COUNT(*) FROM uev_ods.occupancy` = 4344 |
| 4 | MR explode | `hadoop jar uev-mr.jar com.uev.mr.WideToLong ...` | 长表行数 ≈ 275×4344 |
| 5 | 质量检查 | `hadoop jar uev-mr.jar com.uev.mr.DataQualityCheck ...` | 产出 dq_zone_stat |
| 6 | DWD 维表 | 手写 SQL（含 POI 聚合、电价统计） | `COUNT(*) = 275` |
| 7 | DWS 汇总 | Spark SQL 批量跑 | `COUNT(*) = 275×181` |
| 8 | ADS 产出 | Spark SQL 算 7 张 ADS 表 | 每张表有数据 |
| 9 | 导出 MySQL | `sqoop export` × 7 | 后端接口能查到数据 |

> 🔴 **第 3 步的坑**：`LOAD DATA INPATH` 是**移动**不是复制，源文件会从 HDFS 消失。
> 建议先 `put` 到临时目录，再 `LOAD DATA` 到正式路径。
