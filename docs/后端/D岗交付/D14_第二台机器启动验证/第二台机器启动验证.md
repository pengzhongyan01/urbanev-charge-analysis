## 二、脚本做了什么（为什么不是一句 `java -jar` 完事）

`start.ps1` 有 6 步，**每一步都是为了挡住一个"换机器必踩"的坑**：

| 步 | 动作 | 挡住的坑 |
|---|---|---|
| 1 | 优先 `JAVA_HOME\bin\java.exe`，否则 PATH；解析主版本，<17 直接退出 | 机器上装着 JDK 8（默认 PATH），跑起来才报 `UnsupportedClassVersionError`，看不懂 |
| 2 | 三个候选位置找 jar（脚本同目录 / `backend\target` / 上一级） | 换机器后 jar 路径不对，`java -jar` 报 `Unable to access jarfile` |
| 3 | `Get-NetTCPConnection` 查端口占用 | 8080 被别的服务占着，启动静默失败 |
| 4 | TCP 探测 MySQL 端口 | 忘了起数据库；**这里只警告不退出**，因为降级模式也能跑（见 D13） |
| 5 | 组装参数启动，日志落 `run_<port>.log` | 日志只在控制台，答辩时窗口一关全没了 |
| 6 | 轮询 `/api/health` 最多 60 秒，进程退出就打印日志尾部 | "看起来启动了其实没起来"——这是最坑的一种 |

> 第 6 步是关键：**不用人肉去浏览器点一下看有没有起来**，脚本自己判断并给出明确结论。

## 三、第二台机器怎么跑（6 步，照着做）

### 前置准备（一次性）
1. 装 **JDK 17**（不是 8！），配 `JAVA_HOME`：
   ```powershell
   # 临时生效（当前窗口）
   $env:JAVA_HOME = "C:\devtools\jdk\jdk-17.0.21+9"
   # 永久生效（推荐）
   [Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\devtools\jdk\jdk-17.0.21+9", "User")
   ```
2. 装 **MySQL 8**，建库导数据（两个脚本按顺序）：
   ```powershell
   mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS uev_charge DEFAULT CHARSET utf8mb4;"
   mysql -u root -p uev_charge -e "source C:/temp/sql/01_schema.sql"
   mysql -u root -p uev_charge -e "source C:/temp/sql/02_seed_mock.sql"
   ```
   > ⚠️ `source` 要求**纯英文路径**，中文目录会报 `Failed to open file`（本机踩过）。
3. 拷过去两样东西：`backend\`（含 `target\uev-charge-analysis.jar`）和 `D14\start.ps1`。

### 启动
4. 自检（不启动，先看环境对不对）：
   ```powershell
   .\start.ps1 -Check
   ```
5. 启动：
   ```powershell
   .\start.ps1 -Port 8080 -DbPassword "你的root密码"
   ```
6. 自测（另开一个窗口）：
   ```powershell
   .\scripts\smoke_test.ps1 -Base http://127.0.0.1:8080/api
   # 期望：通过 15　失败 0
   ```

### 停止
```powershell
.\start.ps1 -Stop -Port 8080
```

## 四、5 个常见坑（都是真踩过的）

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| 1 | `UnsupportedClassVersionError: class file version 61` | 用了 JDK 8 | 设 `JAVA_HOME` 指向 JDK 17；`java -version` 确认 |
| 2 | `Failed to open file 'C:/Users/.../01_schema.sql'` | `mysql source` 打不开中文路径 | 把 sql 复制到 `C:\temp\sql\` 再 source |
| 3 | 启动成功但所有接口 503 | MySQL 没起 / 库名错 / 密码错 | 先看 `run_8080.log` 里的 `Communications link failure`；用 `-DbPassword` 传密码 |
| 4 | 接口返回的中文是乱码 `???` | 启动参数 `-Dfile.encoding=UTF-8` 没生效 | PowerShell 里参数**必须加引号**：`"-Dfile.encoding=UTF-8"`（不加会被拆坏） |
| 5 | 前端调不到接口，控制台报 CORS | 后端没配 `@CrossOrigin` 或没走 `WebConfig` | 本项目已在 `WebConfig` 统一配 CORS，确认别在 Controller 上重复配 |

> 第 4 条特别隐蔽：不加引号时 PowerShell 会把 `-Dfile.encoding=UTF-8` 拆成两段传给 JVM，
> 结果是"启动成功、日志正常、中文全变问号"。**这个坑写进文档是给下一台机器的人省两小时。**

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| 6 | `At start.ps1:78 char:92 … The string is missing the terminator` | 脚本是 UTF-8 **无 BOM**，Windows 自带 PowerShell 5.1 按 ANSI 解码中文注释，直接语法错 | 脚本已改为 **UTF-8 with BOM**；若手改过脚本请另存为"UTF-8 带 BOM" |
| 7 | 冒烟测试 15 条全部 `异常：A parameter cannot be found that matches parameter name 'SkipHttpErrorCheck'` | `-SkipHttpErrorCheck` 是 PowerShell 7 才有的参数，组员机器多为 5.1 | 冒烟脚本已去掉该参数，改为 try/catch 取异常里的响应体，两个版本行为一致 |
| 8 | `start.ps1 -Check` 在 5.1 下停在 `[1/6]` 并抛 `NativeCommandError` | `java -version` 写 stderr，`2>&1 \| Out-String` 在 5.1 会变成异常记录 | 已改为经 `cmd /c` 重定向取版本号 |

> 第 6–8 条都是 2026-11-24 用 **Windows 自带 PowerShell 5.1** 实测时暴露的：同一份脚本在
> pwsh 7 上完全正常、在 5.1 上直接崩。已全部修复并在 5.1 下复测：`-Check` 四步全 OK、
> `smoke_test.ps1` 输出 **通过 15 / 失败 0**（便携 JDK17 + 包内 jar + MySQL 8）。
