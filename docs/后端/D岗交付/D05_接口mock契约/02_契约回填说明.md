# 契约回填说明（D05 第二步）

> 配套文件：`01_mock_JSON样例.md`（12 个接口的 mock 报文）
> 回填目标：`docs/contracts/03-接口规范.md`（A 岗统稿的团队契约）
> 状态：16 个接口的路径、方法、入参、出参字段已全部回填，契约与实现一致（`scripts/check-contracts.sh` 可校验）。

## 一、为什么要回填

契约不是一次性写死的：E 岗先给出指标口径与字段含义，C 岗按契约写前端、按 mock 画图，
D 岗把 mock 落成真实接口后，必须**把实际返回结构反写回契约**，否则三处（契约 / 后端 / 前端）会各说各话。
这就是"回填"这一步的意义——把接口实现的真实字段名、类型、示例值同步回契约，让下发口径唯一。

## 二、回填了什么（逐项）

| 接口 | 回填内容 | 与 mock 的差异 |
|---|---|---|
| `/api/auth/login` | 出参补 `token`、`expiresIn`；入参固化 `username`/`password` | mock 只有 token 无过期秒数，实现补 `expiresIn=28800` |
| `/api/auth/me` | 出参 `username`/`nickname`/`role` 三字段定名 | 与 mock 一致 |
| `/api/health` | 出参补 `mysql`/`redis`/`regionCount` 三个探针字段 | mock 未含探针，实现新增（D13 降级证据依赖它） |
| `/api/dashboard/kpi` | 6 个指标卡的字段名与单位（kWh / 比值 / 计数） | mock 用 `null` 占位，实现填真实类型 |
| `/api/zones` | `total` + `list[]` 分页外壳 | mock 只有数组，实现外套统一 Result |
| `/api/zones/occupancy` | 每条补 `occupancyRate`、`pileCount` | 字段名与 E 岗指标定义表对齐 |
| `/api/zones/{zoneId}` | 路径参数 `zoneId` 定名；出参 `poiTotal`/`chargeCount` | 与 mock 一致 |
| `/api/charts/hourly` | 24 点数组 + `hour`/`kwh` 字段名 | mock 为 4 点示例，实现为 24 点 |
| `/api/charts/imbalance` | `rankNo`/`imbalanceIndex` 命名对齐 E 岗 | 字段名按 E 岗口径改过一次 |
| `/api/charts/price-elasticity` | `tou`/`flat` 双序列结构 | mock 为单序列，实现拆双序列 |
| `/api/charts/forecast` | 补 `mape` 字段（模型精度随响应下发） | mock 无该字段，实现新增 |
| `/api/charts/suggestions` | `currentPiles`/`suggestedPiles`/`reason` | 与 mock 一致 |
| `/api/charts/volume-deviation` | `deviation` 定义（|预测-实际|/实际） | 与 E 岗定义表一致 |
| `/api/charts/poi-correlation` | `poiTotal`/`poiDensity` | 与 mock 一致 |
| `/api/dictionary` | 返回 CSV 文本 + 行数 | mock 为示例 3 行，实现 4344 行 |
| `/api/system/cache-stats` | `hitAvg`/`missAvg`/`speedup` 三个统计量 | mock 无，实现新增（D07 用） |

## 三、口径约定（回填时确认的三条）

1. **统一外壳**：所有接口返回 `Result{code,message,data}`，`code=200` 为成功；分页数据放 `data.total` + `data.list`。
2. **命名**：驼峰、与 `docs/contracts/02-指标定义表.md` 的指标英文名一致（如 `occupancyRate`、`imbalanceIndex`），不另起别名。
3. **单位**：电量 kWh、功率 kW、金额元、比率 0–1 小数（不写成百分数字符串），时间戳毫秒。
