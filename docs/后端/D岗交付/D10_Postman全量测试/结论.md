# 结论（D10 · Postman 全量测试）

> 每张图一句结论。16 张图 = 16 条，编号与文件名一一对应；括号里是截图上 Postman 自报的耗时/体积。

| 图 | 一句结论 |
|---|---|
| `实测响应_01_health.png` | 健康检查 12 ms 返回 `regionCount=275`、`mysql=UP`、`redis=DOWN`，`status=DEGRADED` 是没装 Redis 时的设计性降级，不是接口坏了。 |
| `实测响应_02_login.png` | 登录 397 ms 换回 sign 完整的 JWT 与 `expiresIn=28800`、`roleCode=ADMIN`，证明鉴权链路真的跑通，令牌不是前端自己造的。 |
| `实测响应_03_me.png` | 带 token 换取 `username=admin / realName=系统管理员 / roleCode=ADMIN`，且响应体只有 440 B、**没有一个密码字段**，说明敏感字段已被拦在序列化层。 |
| `实测响应_04_kpi.png` | 一次 9.11 KB 把 6 个指标全给齐（275 站 / 23441 桩 / 0.4587 占用率 / 904822.6 电量），和契约逐项对得上，首页数字不是拼出来的。 |
| `实测响应_05_zones.png` | `total=275` 与 `zones` 数组同时返回、36.48 KB，证明"总数"和"当前批次"在接口层就分开了，前端不用自己算分页基数。 |
| `实测响应_06_occupancy.png` | 275 条扁平的 `zoneId/经纬度/avgOccupancy/maxOccupancy` 一次给全（36.46 KB），可直接喂 ECharts 地图散点，前端不用再二次转换结构。 |
| `实测响应_07_zone_detail.png` | 分区 140 一次请求同时拿到基础指标（310 桩 / 2252 POI）与 `peakHours`，685 B 就把详情页要的东西闭环了，不是两次拼接。 |
| `实测响应_08_hourly.png` | 24 个 `hourOfDay` 齐全且 `gap = demandShare − supplyShare` 数值自洽，说明供需两组份额是同一口径算出来的。 |
| `实测响应_09_imbalance.png` | `limit=10` 生效、`rankNo` 从 1 起连续，证明排名用的是库内算好的值，后端没有二次计算导致口径漂移。 |
| `实测响应_10_price.png` | 一次返回 `TOU`/`FLAT` 两组各 24 点（4.01 KB），前端画双曲线不用再发一次请求，`avgPriceGap` 也随响应给出。 |
| `实测响应_11_forecast.png` | 分区 140 返回整段时序与 `MAPE=5.92`，`predictVolume 33.06` 对 `actualVolume 32.91`，说明预测接口给的是完整曲线而不是抽样点。 |
| `实测响应_12_suggestions.png` | `currentPiles=83`、`suggestedPiles=10` 并列，`reason` 是完整中文句——**"新增 10 个"不是"变成 10 个"**，这个差别写进了数据里而不是靠口头解释。 |
| `实测响应_13_volume_dev.png` | 双口径电量（`volume 8882.5` vs `volume11kw 6409.72`）与 `deviation 0.2784` 同一行返回，偏差可以直接在页面上讲清楚。 |
| `实测响应_14_poi.png` | `poiTotal / poiDensity / pileDensity / avgOccupancy` 同列（如分区 106：1627 个 POI、密度 17.64），支撑"POI 越密占用率越高"的关联结论。 |
| `实测响应_15_dictionary.png` | 12 个源文件的口径齐全（`occupancy.csv` 4344 行、粒度"分区×小时"），前端"数据源说明"页不必再手写一张静态表。 |
| `实测响应_16_cache_stats.png` | 接口自报 `hitAvgMs=0.005` vs `missAvgMs=14.272`、`speedup=2667.596`，用缓存自己的计数器证明缓存生效，不靠自述。 |

**整体一句结论：**
> 16 个接口在 Postman 里挨个点出来，全部 `HTTP 200`、`code=200`、四字段完整，耗时 12–397 ms、体积 440 B–36.48 KB；
> 这套截图的用处不是"证明我调通了"，而是**当老师问"这个字段到底是什么数"时，有一张能指着看的原始界面**。

> 口径注：16 号的速度倍数取自本次界面实测（0.005 vs 14.272 ms）；D07 基准脚本另测到 0.003 vs 1.952 ms（650.7×）。
> 两处是不同轮次的采样，量级一致（都是千倍级），报告里引用时只取一处，不要混着写。
