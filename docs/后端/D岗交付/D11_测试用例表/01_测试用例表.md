## 二、六类用例的设计理由（为什么是这几条）

### 1. 功能用例：**一个接口一条，不拆正常/异常**
`F-01~F-16` 与 D06 的 16 个接口严格一一对应。
每条只断言"这个接口最容易错的那个点"，而不是把"能返回 200"当功能用例：
- F-04 断言 `275 / 23441 / 0-1`（口径，不是"有数据"）
- F-05 断言 `total=275` 而 `zones` 只 6 条（分页语义）
- F-12 断言 `suggestedPiles` 是新增数、`reason` 是整句（语义）

> **为什么这样设计**：接口能返回 200 是最低要求，写进用例表没有信息量。
> 真正会出事的是"字段含义被改错"——比如把"新增 10 个"理解成"变成 10 个"。

### 2. 安全用例：只测 4 条，但每条都是"会丢分"的点
- S-01/S-03：令牌缺失/篡改 → 401（不是放行，也不是 500）
- S-02：错误提示**不区分**账号不存在还是密码错（防账号枚举）
- S-04：查库确认密码是 `$2a$` 密文（参考作业 6 处明文密码是硬伤）

### 3. 异常用例：E-05 是这套用例里最重要的一条
`GET /api/hours/xx`（路径拼错）必须返回 **404**，不能是 500。
Spring Boot 3 默认抛 `NoResourceFoundException`，不处理就变 500——
**一个拼错的路径让老师以为后端崩了**，这是最常见的"冤枉"。

### 4. 性能用例：三组数据对应三个口径
| 用例 | 口径 | 数值 |
|---|---|---|
| P-01 | 服务端未命中耗时 | 1.952 ms |
| P-02 | 服务端命中耗时 / 加速比 | 0.003 ms / 650.733× |
| G-06 | HTTP 端到端 | 9.1 ms → 6.1 ms |

> 三条数据必须同时出现，否则会被质疑"650 倍为什么页面没变快"。
> 答案在 D07：**缓存省的是查库那一段，不是网络和 JSON 序列化。**

### 5. 降级用例：全部"真停真测"
- D-01：本机**没装 Redis**，启动即复现降级，日志有 WARN 原文
- D-02：`mysqladmin shutdown` 停掉 3307 实例后测未命中接口 → 503
- D-03：停机前缓存的 KPI 仍返回 200（缓存是故障时的缓冲垫）
- D-04：`health` 报 `DEGRADED` 而不是崩溃

### 6. 工程用例：把"规范"变成可执行的检查
- G-01/G-02 → `mvn test` 7 例
- G-03 → `scripts/smoke_test.ps1` 15 项
- G-04 → 审查 5 份 Mapper XML 是否只 `FROM v_*`
- G-05 → `query_log` 的 `hit_cache` 字段是否真的有 0/1 两类

## 三、怎么执行（三条命令搞定）

```powershell
# ① 单元测试（7 例）
cd backend
mvn test

# ② 接口冒烟（15 项断言）
powershell -File ..\scripts\smoke_test.ps1 -Base http://127.0.0.1:18080/api

# ③ 缓存与降级（手动，看数值）
curl.exe -s -X POST "http://127.0.0.1:18080/api/system/cache-stats/reset"
1..6 | ForEach-Object { curl.exe -s -o NUL -w "%{time_total}`n" "http://127.0.0.1:18080/api/charts/imbalance?limit=7" }
curl.exe -s "http://127.0.0.1:18080/api/system/cache-stats"
```

**Postman 方式**：导入 `D10/UrbanEV_D岗_16接口.postman_collection.json`，Run 集合，16 个请求带断言。

## 五、用例表的两个诚实说明

1. **没有自动化 UI 测试**：前端归 C 岗，D 岗只对接口负责；接口层已用 43 条用例 + Postman 集合覆盖。
2. **性能数据是单机数据**：1.952ms → 0.003ms 是本地 MySQL + 本地缓存的结果，不是分布式压测。
   报告里写的是"本机实测"，没有夸大成"生产环境 QPS 提升"。

> 这两条写进报告，比声称"全链路自动化测试"更可信——**老师见过太多吹的**。
