## 二、字段名怎么对齐（不写 resultMap 的理由）

```yaml
# application.yml
mybatis:
  configuration:
    map-underscore-to-camel-case: true
```

| 数据库字段 | VO 字段 | 是否需手写映射 |
|---|---|---|
| `zone_id` | `zoneId` | 自动 |
| `avg_occupancy` | `avgOccupancy` | 自动 |
| `hit_cache` | `hitCache` | 自动 |
| `volume_11kw` | `volume11kw` | 自动（数字保留在驼峰中） |

**约定**：视图字段名 = 下划线小写；VO 字段名 = 小驼峰。**只要两边遵守这一个约定，13 条 SQL 一条 resultMap 都不用写。**
这比逐字段写 `<resultMap>` 省下上百行，也不容易写错。

## 三、四条 SQL 写法约定（防坑清单）

### 1. 只用 `#{}`，禁止 `${}`
```xml
LIMIT #{limit}          <!-- ✅ 预编译，参数化 -->
LIMIT ${limit}          <!-- ❌ 字符串拼接，可被注入，且类型不受控 -->
```
`limit` 是 `int` 且已被 `@Max(100)` 校验，但**仍然用 `#{}`** —— 规范不能因为"这次安全"就破例。

### 2. `<where>` + `<if>`，不手写 `WHERE 1=1`
```xml
<where>
    <if test="zoneId != null and zoneId != ''">AND zone_id = #{zoneId}</if>
    <if test="hourFrom != null">AND hour_of_day &gt;= #{hourFrom}</if>
</where>
```
`<where>` 会自动去掉开头多余的 `AND`，也不用写 `1=1` 这种看着就外行的东西。
注意 XML 里 `>=` 必须写成 `&gt;=`，否则解析报错（第一次写的时候踩过）。

### 3. 排序 + LIMIT 一定同时出现
```xml
ORDER BY imbalance DESC LIMIT #{limit}
```
没有 `ORDER BY` 的 `LIMIT` 在 MySQL 里结果**不稳定**（可能两次查出不同的 10 条），前端图表会闪。

### 4. 视图里不做业务计算
`gap`、`deviation`、`mape` 这些值**已经在 ADS 层算好**（E 岗口径），视图只做字段投影。
后端**不重复计算**，避免"同一指标两套算法"这种最难解释的问题。

## 四、"视图可整体替换"——这是接视图的真正价值

实测过的场景：B 岗（苏静）把 `v_zone_occupancy` 的口径从"全期平均"改成"最近 30 天平均"，
只需要：

```sql
-- B 岗改这一处
CREATE OR REPLACE VIEW v_zone_occupancy AS
SELECT zone_id, longitude, latitude, ... FROM zone_occupancy WHERE dt >= '2025-10-21';
```

**D 岗这边：0 行改动。** 5 份 Mapper XML 不用动、Service 不用动、Controller 不用动、前端不用动。

为什么能做到：**视图名和字段名是 D 与 B 之间的稳定接口**，口径变化被挡在视图这一层。
这就是"契约"三个字在工程上的具体兑现 —— 不是文档写得好听，是真能少改代码。

## 五、联调检查清单（B 岗交 ADS 表后按这个核）

```sql
-- ① 视图全在，且能查
SHOW FULL TABLES WHERE Table_type = 'VIEW';         -- 应返回 10 个 v_*
SELECT * FROM v_kpi_overview;                        -- 应有 1 行
SELECT COUNT(*) FROM v_zone_occupancy;               -- 应为 275
SELECT COUNT(*) FROM v_zone_hour_profile;            -- 应为 6600

-- ② 字段名与 Mapper 一致（不一致会返回 null 而不是报错，最难查）
SELECT zone_id, avg_occupancy, max_occupancy, charge_count, poi_total FROM v_zone_occupancy LIMIT 1;

-- ③ 类型对得上（DOUBLE 不要是 VARCHAR，否则前端 toFixed 会炸）
SELECT COLUMN_NAME, DATA_TYPE FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA='uev_charge' AND TABLE_NAME='v_kpi_overview';
```

> 第 ② 条特别提醒：**MyBatis 字段名写错不会报错，只会给你 null**。
> 所以联调时先看一行原始数据，比在前端查"为什么图表是空的"快 10 倍。
