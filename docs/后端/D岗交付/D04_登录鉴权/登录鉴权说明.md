# 登录鉴权说明（D04）

> 维护人：杨姗姗（D 岗）　|　版本 v1.0　|　2026-11-20　|　技术栈：Spring Boot 3.2.5 + jjwt 0.12.5 + spring-security-crypto

---

## 一、整体流程（一句话版）

```
前端 POST /api/auth/login {username,password}
   → AuthService 查 sys_user → BCrypt.matches() 校验
   → JwtUtil 签发 HS256 令牌（sub=用户名, role=角色, 2 小时过期）
   → 返回 {token, tokenType:"Bearer", expiresIn, user:{...}}
前端后续请求带 Authorization: Bearer <token>
   → AuthInterceptor 解析 → 写入 AuthContext → Controller 取当前用户
```

## 二、四个设计决定（答辩必讲）

### 决策 1：密码用 BCrypt，而不是 MD5 / 明文
| 方案 | 问题 |
|---|---|
| 明文 | 参考作业的硬伤之一，老师一眼毙 |
| MD5 | 彩虹表秒破，且同一密码哈希值相同（能看出两个账号同密码） |
| **BCrypt** | 自带随机盐（同一密码每次哈希都不同）+ 可调 cost，是业界默认 |

库里存的是 `$2a$10$AizSB.CVvR9Y0agOlJjXbeTzWi3CjUt4D3OA.TlDq4fqyMpVyWiJK`（cost=10，60 字符）。
**`password_hash` 字段加了 `@JsonIgnore`，任何接口都不会把它吐给前端。**

### 决策 2：JWT 用 HS256 对称签名，密钥从配置读 + 启动校验
```java
// JwtUtil 构造时校验，密钥少于 32 字节直接启动失败
if (secret.getBytes(StandardCharsets.UTF_8).length < 32) {
    throw new IllegalStateException("uev.jwt.secret 长度不足 32 字节，HS256 密钥过短不安全");
}
```
- **为什么校验**：jjwt 0.12 对短密钥会抛 `WeakKeyException`，与其运行到第一次登录才炸，不如启动就炸。
- **密钥放哪**：`application.yml` 里给默认值，生产用环境变量 `UEV_JWT_SECRET` 覆盖，`${UEV_JWT_SECRET:默认值}`。
- 有效载荷只有 `sub`（用户名）、`role`、`iat`、`exp`，**不放手机号等敏感信息**（JWT 是 base64，不是加密）。

### 决策 3：拦截器 + 白名单，而不是在每个 Controller 里写 if
```java
// AuthInterceptor.preHandle
if (!authEnabled) return true;                      // 总开关关闭 → 全部放行（联调期）
if ("OPTIONS".equals(request.getMethod())) return true;  // 预检请求放行，否则 CORS 全挂
if (isWhiteList(path)) return true;                 // /api/health、/api/auth/login
String token = resolveBearer(request);              // 取 Authorization 头
if (token == null) throw BusinessException.unauthorized("未携带令牌，请先登录");
AuthUser user = jwtUtil.parse(token);               // 解析失败抛 401
AuthContext.set(user);
```

**顺序很重要**：`OPTIONS` 必须在取令牌之前放行。
否则前端跨域预检请求被 401，浏览器只会显示一个莫名其妙的 CORS 错误，非常难查。

### 决策 4：鉴权默认关闭（`uev.auth.enabled=false`）
- **原因**：C 岗（贺欢欢）联调时不该被登录卡住；D10 Postman 里也预留了"先登录拿 token"的一步。
- **答辩怎么演示**：启动时加 `--uev.auth.enabled=true`，现场演示 401 → 登录 → 200 的完整链路（见下）。

## 三、接口定义

### POST `/api/auth/login`
请求：
```json
{ "username": "admin", "password": "uev123456" }
```
成功响应：
```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJhZG1pbiIsInJvbGUiOiJBRE1JTiIsImlhdCI6MTc5NTE1OTY1NSwiZXhwIjoxNzk1MTY2ODU1fQ.xxxxx",
    "tokenType": "Bearer",
    "expiresIn": 7200,
    "user": { "username": "admin", "realName": "杨姗姗", "roleCode": "ADMIN" }
  },
  "timestamp": 1795159655771
}
```

### GET `/api/auth/me`
请求头 `Authorization: Bearer <token>`，返回当前登录用户（不含密码字段）。

## 四、实测记录（2026-11-20，本机 18080 端口，原样粘贴）

| 场景 | 请求 | 结果 |
|---|---|---|
| 正常登录 | `POST /api/auth/login` admin/uev123456 | `code 200`，token 长度 **172**，expiresIn 7200 |
| 凭令牌取用户 | `GET /api/auth/me` 带 Bearer | `code 200`，返回 `{"username":"admin","realName":"杨姗姗","roleCode":"ADMIN"}` |
| 不带令牌 | `GET /api/auth/me` 无头 | `code 401`「未携带令牌，请先登录」 |
| 密码错 | `POST /api/auth/login` admin/wrong | `code 401`「用户名或密码错误」 |
| 令牌伪造 | 改掉 token 最后一位 | `code 401`「令牌已失效，请重新登录」 |
| 令牌过期 | `exp` 改成过去时间 | `code 401`「令牌已失效，请重新登录」 |

> 注意：以上 401 的 **HTTP 状态码依然是 200**，前端靠 body 的 `code` 判断 —— 见 D02 第一节。

## 五、答辩演示脚本（30 秒）

```powershell
# 1) 用开启鉴权的方式启动
java -jar backend\target\uev-charge-analysis.jar --uev.auth.enabled=true

# 2) 无令牌访问 → 401
curl.exe -s "http://localhost:8080/api/auth/me"

# 3) 登录拿令牌
curl.exe -s -X POST "http://localhost:8080/api/auth/login" -H "Content-Type: application/json" -d "{\"username\":\"admin\",\"password\":\"uev123456\"}"

# 4) 带令牌访问 → 200
curl.exe -s "http://localhost:8080/api/auth/me" -H "Authorization: Bearer <上一步的token>"
```

配上 D13 的 `query_log` 表，可以现场展示"同一个账号 3 次请求、第 2 次命中缓存"，
把"鉴权"和"审计"两件事一起讲完。
