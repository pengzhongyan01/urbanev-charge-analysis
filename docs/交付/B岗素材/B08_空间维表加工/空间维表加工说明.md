# 空间维表加工说明（苏静 · B 岗）

空间维表加工是把「没有分区标识」的空间数据落到 275 个交通分区上的过程，产出四类维表，
是分析供需空间错配的数据基础。

---

## 一、分区维表（dim_zone_info）

来源 `inf.csv`（275 行：TAZID / longitude / latitude / charge_count / area / perimeter），
整合 POI 计数与电价波动特征后形成 15 字段综合维表（见 02_dwd.sql ④）。

**★ 致命坑**：`inf.csv` 行序 ≠ 时序表列序（inf 第 1 行是 1066，occupancy 第 1 列是 102），
**必须按 `TAZID = zone_id` 显式 join，禁止按行号对齐**——否则所有空间分析全部失真且极难发现。

## 二、POI → 分区聚合（zone_poi_count）

- 数据量：`poi.csv` **712,135 条**，仅 3 类 `primary_types`
  （lifestyle services 55.2% / business and residential 25.7% / food and beverage services 19.0%）
- 方法：MapReduce `PoiZoneJoin.java`，Map 端广播 275 个分区中心点，Haversine 球面距离归入最近分区
- 实测：1km 半径命中 **274/275 分区**，1km 内 POI 总数 722,585
- 半径选 1km 的依据：3km 时每分区平均命中约 1.8 万个 POI，区分度过低；1km 分区间差异明显

## 三、邻接边表（adj 展开）

来源 `adj.csv`（275×275 的 0/1 邻接矩阵）。供空间邻域分析（如相邻分区需求对比）用，
把矩阵展开为边表 `(zone_from, zone_to, is_adj)`：

```sql
-- 邻接边表（Hive 宽表列转行，仅保留相邻对）
CREATE TABLE IF NOT EXISTS uev_dwd.zone_adj_edge (
  zone_from STRING COMMENT '源分区',
  zone_to   STRING COMMENT '目标分区',
  is_adj    INT    COMMENT '1=相邻'
) STORED AS ORC;

-- 由 uev_ods.adj 宽表展开（示意：275 列 → 边表，is_adj=1 的行保留）
INSERT OVERWRITE TABLE uev_dwd.zone_adj_edge
SELECT t.zone_from, t.zone_to, t.is_adj
FROM uev_ods.adj
LATERAL VIEW STACK(275, ... ) t AS zone_to, is_adj  -- 实际由脚本动态生成
WHERE t.is_adj = 1;
```

## 四、气象站映射（zone_weather）

气象数据只有 2 个站（`weather_airport` 宝安机场站 / `weather_central` 福田站），
每个分区须映射到「最近气象站」：

```sql
-- 分区 → 最近气象站（用 inf 经纬度与两站经纬度算距离）
CREATE TABLE IF NOT EXISTS uev_dwd.zone_weather_map (
  zone_id       STRING,
  nearest_station STRING COMMENT 'airport / central',
  dist_m        DOUBLE COMMENT '到最近气象站距离（米）'
) STORED AS ORC;
```

**★ 两个坑**（契约 01）：
1. 气象时间格式 `2022/9/1 0:00`（斜杠 + 无补零）与时序表 `2022-09-01 00:00:00` 不一致，join 前须统一格式。
2. 只有 2 个气象站，不是每个分区都有 → 需做分区到最近气象站映射。

## 五、实测结果（报告 3.4.4 用）

| 项 | 值 |
|---|---|
| POI 总条数 | 712,135 |
| 空间连接方式 | Haversine，1km 半径 |
| 匹配分区 | 274 / 275（99.6%） |
| 未匹配 | 1 个（中心点 1km 内无 POI） |
