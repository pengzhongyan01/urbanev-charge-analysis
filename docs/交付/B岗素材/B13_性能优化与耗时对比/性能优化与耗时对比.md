# 性能优化与耗时对比（苏静 · B 岗）

> 实测基准：`scripts/python_etl.py` 全量实跑 181 天 / 4,344 小时 / 712,135 POI，
> 产出 7 张 ADS 表，**耗时 66.2 秒**。以下优化项为 Hive 侧与等价 Python 侧共用的工程手段。

## 一、四项核心优化

| # | 优化项 | 优化前 | 优化后 | 原理 |
|---|---|---|---|---|
| ① | Map 端广播（POI 空间连接） | 笛卡尔积 71 万 × 275 = **1.96 亿次**距离计算 | Map 端加载 275 分区中心点，逐条归最近分区 | 避免笛卡尔积，POI 连接从分钟级降到秒级 |
| ② | 按 dt 分区裁剪 | 全量扫描 4344 小时 | 只扫目标日期分区 | 分区裁剪，查询/重算按需读 |
| ③ | ORC + Snappy 压缩 | TEXTFILE 文本 | ORC 列存 + Snappy | 列式压缩，存储减半、扫描只读相关列 |
| ④ | 内存复用（逐指标处理） | 6 张长表全驻留 ≈ 4GB+ | 标量聚合先抽出，矩阵用完即 del | 峰值内存从 4GB 降到 **1.2GB** |

## 二、耗时对比（实测）

| 环节 | 耗时 |
|---|---|
| 数据加载 + 宽转长 + 清洗（6 指标） | 秒级 |
| POI 空间连接（1km 半径） | 秒级 |
| ADS 7 张表 + 5 张洞察表计算 | 秒级 |
| **全量 ETL 总计** | **66.2 秒** |

```properties
# CLUSTERED BY (zone_id) INTO 16 BUCKETS
```

## 四、答辩话术（PPT 第 10 页）

> 性能优化的价值不在「堆参数」，而在「识别瓶颈再对症下药」：
> POI 连接是笛卡尔积瓶颈 → Map 端广播；宽表反复扫描 → dt 分区裁剪；
> 存储冗余 → ORC+Snappy；内存不足 → 逐指标处理 + 及时释放。
> 最终全量 ETL 66.2 秒、内存峰值 1.2GB，一台 8GB 笔记本即可复现。
